Presenter Cheat Sheet

Use this screen when you need a fast reset mid-meeting. It keeps the discipline tight and reduces the risk of drifting into product stacking or vague resilience language.

Source-grounded: 4, 9, 14, 15, 16, I, H Derived: compact workshop prompts

Opening line

I am not going to start with products. I am going to start with the interconnection problem you are solving, the traffic that matters, where control should sit, what failure you must survive, and what operating model still works after go-live.

First five questions

  • What is the primary trigger?
  • Which traffic class is driving the issue?
  • What is painful in the current state?
  • How do you reach the interconnection layer today?
  • What function is actually needed after arrival?

Three anchor lines

  • Reach and service choice are not the same decision.
  • Private pathing and encrypted pathing are related, but not identical claims.
  • Do not say resilient without naming the failure domain.

What not to say

  • This solves everything.
  • Private means secure.
  • Peering and internet are basically the same.
  • Highly available, without naming the failure.
  • Here are all the products.

Closing line

The value is not only that we can connect. The value is that we can connect with clearer ownership, cleaner control placement, better resilience discipline, and a more supportable operating model. To move from reference architecture to high-level design, these are the decisions we must now close.
